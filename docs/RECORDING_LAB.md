# 예약 녹음 검증 기록

## 현재 구현

Android용 Flutter 테스트 앱과 Kotlin 마이크 서비스를 구현했다. 검증 대상은 미리 실행한 짧은 테스트 세션이며, 실제 Google Calendar 일정은 아직 사용하지 않는다. 녹음 중단·저장 실패를 포함한 결과를 오디오와 별도 기록으로 보관한다.

## 테스트 절차

| ID | 방법 | 확인할 결과 |
|---|---|---|
| A1 | 기본 모드에서 2분 후/1분 녹음 | 앱을 열어 둔 상태로 정각 시작, 자동 종료, 파일 재생 |
| A2 | 10초 후/10초 녹음 시작 전 홈 화면으로 이동 | 예약 취소, 파일 수집 없음, 자동 재시작 없음 |
| A3 | 즉시/1분 녹음을 시작한 뒤 화면 잠금 | 이미 시작한 녹음 유지와 자동 종료, 실제 음성 누락 여부 |
| A4 | 화면 잠금 실험을 켜고 2분 후/1분 예약, 잠금 | 시작 전 소리 수집 없음, 예약 시각 시작 여부, 잠금 후 파일 마무리 |
| A5 | 녹음 중 지속 알림의 종료 버튼 선택 | 종료·저장, 마이크·서비스·WakeLock 해제 |
| A6 | 테스트 중 최근 앱 목록에서 제거 | 예약 취소 또는 녹음 종료·저장 |
| A7 | 테스트 중 강제 종료 후 앱 재실행 | 중단 기록, 자동 재시작 없음, 남은 파일은 확인 필요로 표시 |
| A8 | 녹음 중 전화/다른 마이크 앱 사용 | 오류나 무음 구간 확인; 오디오를 직접 재생하여 결과 기록 |
| A9 | 권한 거절 또는 알림 채널 차단 | 시작 버튼 비활성화와 설정 안내 |
| A10 | 녹음 후 재생·내보내기·삭제·앱 재실행 | 파일 접근, 사용자 삭제 확인, 목록 복원 |

각 실기기 테스트는 기기/OS/앱 빌드/모드/예약 시각/실제 시작/실제 종료/실제 음성 재생 확인을 기록한다. 절전·잠금·전화 수신 등 사용 조건도 함께 적는다.

## 상태 구분

- `scheduled`: 서비스가 예약을 접수했으며 아직 마이크 수집을 시작하지 않음
- `recording`: MediaRecorder 시작이 반환됨. 실제 음성이 담겼는지는 재생 확인 필요
- `saved`: 녹음 종료 후 M4A 메타데이터에서 재생 길이를 확인함. 품질 통과 의미 아님
- `cancelled`: 시작 전에 취소됨
- `missed`: 서비스가 시작 시각을 5초 초과하여 놓쳐 새 녹음을 시작하지 않음
- `failed`: 녹음 준비/수집/파일 마무리 중 실패
- `interrupted`: 실행 종료 등으로 정상 마무리 결과를 확인할 수 없음

프로세스가 강제 종료된 경우 실제 종료 시각과 파일 길이를 추정해 채우지 않는다. 남은 파일이 있다고 복구 성공으로 표시하지 않는다. 단조 시계는 대기/녹음 길이에 사용하고, 표시용 실제 시각은 기기 시계를 사용한다. 실행 중 기기 시계를 바꾸면 표시용 시작 차이는 왜곡될 수 있다.

## 이번 작업의 결과

검증일: 2026-09-13. 아래 에뮬레이터 결과와 실기기 검증은 구분한다.

- Android 디버그 APK 빌드 성공: `build/app/outputs/flutter-apk/app-debug.apk`
- `flutter analyze`: 문제 없음
- `flutter test`: 10개 통과. 권한 거절, 예약 값, 미지원 플랫폼, 작은 화면·큰 글자, 중단 시각 표시, 잠금 실험 확인 취소, 재생 요청, 시간 표시, 중복 실행 방지, 비동기 종료 처리 포함
- Android `:app:testDebugUnitTest`: 6개 통과. 단조 시계 기반 시작 판단, 백그라운드 취소, 잠금 실험 대기, 지연 생략 및 입력 제한 검증
- Android 16(API 36) Pixel 7 프로필의 별도 테스트 에뮬레이터에서 아래 실행 결과 확인

| 실행 조건 | 확인한 결과 | 한계 |
|---|---|---|
| 기본 모드, 10초 후 10초 녹음 | 예약보다 666ms 뒤 시작, M4A 10.033초 저장, 녹음함에서 재생 시작 확인 | 실제 음성 품질은 확인하지 않음 |
| 기본 모드, 예약 후 시작 전에 홈 화면으로 이동 | `cancelled / left_foreground`, 마이크 수집 없이 예약 취소 | 제조사별 동작은 추가 확인 필요 |
| 잠금 실험, 2분 후 1분 녹음, 예약 직후 화면 끄기 | 예약보다 594ms 뒤 시작, M4A 60.031초 저장, `saved / duration_reached` | 앱이 보이는 상태에서 사용자가 시작한 짧은 세션만 검증 |
| 잠금 실험 종료 후 | 화면은 계속 꺼진 상태, 서비스 종료 및 WakeLock 해제 확인, 확인 시점에 크래시 로그 없음 | 장시간 절전·앱 강제 종료 후 자동 시작의 근거가 아님 |
| 최종 APK 재설치 후 녹음함 | 기존 기록 유지, 10초/1분 길이 표시, 잠금 실험 파일의 재생 시작 확인 | 내보낸 파일의 외부 앱 재생은 미검증 |

호스트 오디오 입력/출력을 비활성화한 에뮬레이터이므로 파일 생성·메타데이터·재생 시작만 확인했다. 실제 대화가 녹음되거나 사람이 재생 음성을 들었다는 의미가 아니다. 위 시작 지연 두 건도 정각 실행 정확도나 성공률을 보장하는 통계가 아니다.

## 남은 검증

- 실제 Android 휴대폰: 미연결, 음성 및 화면 잠금 실기기 검증 미실시
- A1~A10 전체 실기기 시나리오, 제조사별 절전, 통화·마이크 충돌, 강제 종료·저장 실패, 외부 앱으로 내보내기 및 백업 제외의 실제 효과
- iOS: 빌드/녹음 구현 및 실기기 검증 미실시
- Google 다중 계정 인증과 Calendar 변경 반영: 다음 검증 단계

실제 휴대폰에서 A1~A4부터 확인한 뒤 Google 테스트 계정 두 개와 Calendar API/OAuth 설정을 준비한다. 현재 결과만으로 캘린더 기반 무인 자동 녹음을 제품 지원으로 확정하지 않는다.
